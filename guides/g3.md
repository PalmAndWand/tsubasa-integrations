# g3 configuration for Tsubasa

This manual configuration uses g3's existing named OpenAI provider. It does not
add a native Tsubasa provider or require an upstream change. The config loader,
OpenAI registration, output-budget resolver, and HTTP client were checked at
source commit `9793144520d290a9ea621a06cf7d8322e6fa4a35` (the manifest says
`0.1.0`; no official release binary was available).

## Configure an existing g3 installation

1. Save [g3.toml](../presets/g3.toml) outside your source repository, for example as
   `~/.config/g3/tsubasa.toml`.
2. Replace both `REPLACE_WITH_TSUBASA_API_KEY` values with your Tsubasa key. This
   version's TOML loader uses literal strings; it does not expand environment
   variables in `api_key`. Restrict file access with
   `chmod 600 ~/.config/g3/tsubasa.toml`.
3. Pass the existing file explicitly:

   ```sh
   g3 --config "$HOME/.config/g3/tsubasa.toml" \
     --provider openai.tsubasa-pro 'Explain this function briefly.'
   ```

Use `openai.tsubasa-fast` to select Fast. Both entries use
`https://api.tsubasa.sh/v1`, a 4,096-token output cap, and an explicit 32,768-token
context setting. Planner, coach, and player entries also select Tsubasa Pro.
The named `providers.openai` route preserves the configured output cap; the
separate `openai_compatible` map does not resolve that cap in this source pin.

## Verification limits

Eight loopback cases passed using the unchanged OpenAI client and config source:
both public aliases, JSON and SSE text responses, usage parsing, dedicated-key
selection, and invalid-key errors. Every serialized request passed Tsubasa's
real request schema and context-budget check. The source harness omitted
unrelated provider modules to avoid their unconditional Metal build dependency.

The complete g3 crate, CLI startup, stock prompt, tool execution, and long
sessions were not tested. This is a backend-checked configuration, not a complete
agent qualification. No live Tsubasa inference was exercised. Keep the explicit
context/output limits and check complete CLI requests before relying on a
coding workflow.
